# 관리자 API 연동 검증 기록

검증 기준일: **2026-11-18**. 최신 `main`의 기존 API 서버에 관리자 프런트를 추가한 결과를 대상으로 합니다.

## 1. 수행 결과

| 검증 | 결과 | 확인 범위 |
|---|---|---|
| 실제 API 연동 테스트 | **18개 API, 20개 검증 그룹 통과, 종료 코드 0** | 프런트의 실제 요청 함수 → 별도 Express 서버 → 임시 SQLite |
| Next.js 전체 빌드 | **통과, 종료 코드 0** | `.env.local`의 실제 API 모드, 관리자 7개 경로 및 기존 사장·라이더 경로 포함 |
| 관리자 파일 범위 ESLint | **오류 0개·경고 0개, 종료 코드 0** | 관리자 페이지·컴포넌트·라이브러리·API 테스트 스크립트 |
| 빌드한 화면 서버 응답 | **9개 경로 HTTP 200** | 관리자 7개 경로, 기존 `/owner/login`, `/rider/login`. 관리자 로그인 HTML에서 `ADMINISTRATOR` 문자열 확인 |
| 공통 코드 보존 | **원본 200개 파일 변경 0개** | 최신 `main` 원본 파일의 해시 비교 |
| 기존 관리자 테마 보존 | **CSS 바이트 동일** | `app/admin/baemin-theme.css`를 이전 관리자 버전과 비교 |
| 브라우저 자동 클릭·시각 검증 | **미완료** | Chromium 실행 제한 및 클라우드 브라우저의 로컬 서버 연결 거부로 수행하지 못함 |

빌드 통과는 코드가 배포용으로 컴파일된다는 의미입니다. HTTP 테스트는 요청·응답과 DB 변경 결과를 검증합니다. 이 두 결과로 브라우저의 실제 레이아웃, 모든 클릭 동작, 외부 배포까지 검증했다고 판단하지 않습니다.

화면 서버의 HTTP 200 확인은 `/admin/login`, `/admin`, `/admin/applications`, `/admin/reports`, `/admin/restrictions`, `/admin/orders`, `/admin/members`, `/owner/login`, `/rider/login`에 대해 수행했습니다. 화면 HTML을 제공한다는 확인이며, 클라이언트에서 실행되는 인증·클릭 흐름을 실제 브라우저로 완료했다는 뜻은 아닙니다.

## 2. API 테스트가 확인하는 내용

테스트 파일: `scripts/test-admin-api.mjs`.

모의 응답 대신 `lib/admin/api.js`의 실제 API 모드를 사용합니다. 별도 임시 폴더에 API 서버 코드와 SQLite를 준비하고 테스트를 실행합니다. 기존 프로젝트의 `server/delivery.db`와 사용자가 실행 중인 API 서버는 테스트 대상으로 사용하지 않습니다.

| 영역 | 주요 확인 사항 |
|---|---|
| 인증 | 미로그인 401, 비밀번호 오류, ADMIN 로그인, `/me`, 로그아웃 |
| 권한·연결 | OWNER의 관리자 API 403, 쿠키 전달, CORS 응답, `/api` 경로 조합 |
| 관리자 요약 | 신청·신고·제한 건수가 DB 기록과 일치 |
| 입점 승인·반려 | 목록·상세, 신청 이력과 가게 승인 상태 동시 반영, 사장 조회 결과, 중복 처리 충돌 |
| 신고 처리 | 상세의 리뷰·주문·작성자, 리뷰 숨김, 선택적 작성 제한, 기각, 중복 처리 방지 |
| 리뷰 제한 | 생성·해제·해제 이력, 중복 제한·중복 해제, 고객 역할 검사 |
| 주문 | 번호·이메일·전화번호 검색, 상세·메뉴·옵션·타임라인 |
| 관리자 취소 | ETC 상세 사유 검증, 취소 상태·상담 메모·처리자 저장, 포인트 환불·라이더 상태, 중복 취소 방지 |
| 회원 검색 | 역할 필터, 관리자 제외, 반환 필드 |

테스트에서 사용하는 브라우저 쿠키 전달은 Node의 테스트 도구가 재현합니다. 따라서 서버의 쿠키·CORS 계약을 확인한 결과이며, 실제 브라우저가 쿠키 정책을 적용하는 모든 상황을 자동 클릭으로 확인한 결과는 아닙니다.

## 3. 검증 재실행

Node.js 24 및 화면·API 패키지 설치가 끝난 프로젝트 루트에서 실행합니다.

### API 테스트

```powershell
node scripts/test-admin-api.mjs
```

테스트가 자체 임시 서버와 DB를 준비하므로 별도의 `db:init`이나 실행 중인 API 서버가 필요하지 않습니다. 실행 전 API 서버의 의존성 설치는 필요합니다.

```powershell
npm.cmd run setup:server
```

### 전체 빌드

루트 `.env.local`에서 다음 값을 확인합니다.

```dotenv
NEXT_PUBLIC_API_BASE=http://localhost:4000
NEXT_PUBLIC_USE_MOCK=false
```

```powershell
npm.cmd run build
```

### 관리자 파일 코드 검사

```powershell
npx.cmd eslint app/admin components/admin lib/admin scripts/test-admin-api.mjs
```

이 명령은 관리자 추가 파일을 대상으로 합니다. 공통 서버 전체를 대상으로 한 검사 결과와 구분합니다.

## 4. 사용자 PC에서 확인할 화면 동작

두 개발 서버를 켠 뒤 `http://localhost:3000/admin/login`을 엽니다. 초기 계정은 `admin@test.com / test1234`입니다.

| 확인 | 기대 결과 |
|---|---|
| 로그인 및 새로고침 | 관리자 화면으로 이동하고 세션이 유지됨 |
| 초기 관리자 요약 | DB를 방금 초기화했다면 대기 신청 1건·대기 신고 1건·활성 제한 1건 |
| 입점 신청 4번 처리 | 처리한 탭으로 이동하고 재조회 후 상태 유지 |
| 신고 1번 상세 | 리뷰·주문·작성자 정보와 처리 폼 표시 |
| 제한 전체·해제 탭 | 종료된 제한 2번 이력이 표시됨 |
| 주문 3번의 기타 사유 취소 | 상세 사유와 상담 메모를 각각 입력할 수 있고 저장 후 상세에 표시 |
| 처리 오류 | 입력 오류 또는 중복 처리 오류 메시지가 화면에 표시됨 |
| 목록 마지막 항목 처리 | 존재하지 않는 페이지에 남지 않고 유효한 페이지 표시 |
| 로그아웃 | 로그인 화면으로 이동하고 관리자 API에 다시 로그인 필요 |

이미 API를 사용해 데이터를 변경한 DB라면 초기 ID·건수는 달라질 수 있습니다. 확인하려고 `db:init`을 반복할 필요는 없습니다. `db:init`은 기존 DB를 삭제하므로 의도적으로 초기 상태로 되돌릴 때만 사용합니다.

## 5. 실환경에서 달라질 수 있는 조건

- Node.js 버전, 네이티브 SQLite 모듈 설치 상태, 사용 중인 포트는 사용자 PC에서 확인해야 합니다.
- 화면이 3001번으로 실행되거나 다른 PC의 주소로 접속하면 CORS origin 설정을 함께 확인합니다.
- 같은 브라우저 일반 탭은 역할별 로그인 쿠키를 공유합니다. 동시 시연은 다른 브라우저 또는 일반 창·시크릿 창으로 나눕니다.
- 초기 WAIT 주문은 주문 시각으로부터 10분이 지나면 서버의 자동 취소 대상이 됩니다.
- 외부 공개 배포와 외부 네트워크 접속은 이번 검증 범위에 포함되지 않습니다.
